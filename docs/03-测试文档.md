# 测试文档（Test Plan）

**项目**：TanKing —— FC《坦克大战》网页复刻版
**版本**：v0.3（已评审确认；含 2026-10-19 二次修订）
**日期**：2026-10-19

---

## 1. 测试策略总览

| 层级 | 工具 | 范围 | 时机 | 覆盖目标 |
|---|---|---|---|---|
| L1 单元测试 | Vitest（headless） | `shared/` 纯逻辑：移动、碰撞、地形破坏、道具、计分、AI 决策、PRNG | 随代码持续（TDD 友好） | 行覆盖率 ≥ 85%（sim 目录 ≥ 95%） |
| L2 集成测试 | Vitest + Node（fake WebSocket 客户端） | GameServer + BattleSim 全流程：进房→开局→输入→击杀→结算→再来一局 | 每次合并前 | 关键流程 100% 用例化 |
| L3 端到端测试 | Playwright（多浏览器页） | 真实浏览器：加载页面→联机→实际操作→画面断言 | 冒烟每次合并；全量发布前 | 核心用户旅程 |
| L4 手动联机测试 | 真机局域网（≥3 台设备） | 手感、延迟、防火墙、多浏览器兼容、断线恢复 | 每个里程碑验收 | 验收标准（§7） |
| L5 性能测试 | Node profiler + Chrome DevTools | tick 耗时、快照体积、客户端帧率 | M2/M5 | NFR-1/2 |

**测试可复现性原则**：BattleSim 使用种子化 PRNG，所有 L1/L2 用例固定种子，断言确定性结果；协议消息录制回放（record/replay fixture）用于回归。

## 3. L2 集成测试用例（服务器全流程）

| 用例 | 流程 | 断言 |
|---|---|---|
| IT-01 | fake 客户端 A join → 房间状态 | 返回房间列表/成员，状态 = Waiting |
| IT-02 | 房主设置地图/AI → ready → start | 全员收到 Countdown → Playing 事件，快照开始下发 |
| IT-03 | A 上报移动输入 60 tick | A 的快照位置持续变化且与预期轨迹一致 |
| IT-04 | A 击毁 B（脚本化瞄准） | 双方收到 kill 播报事件，计分板 A+1 |
| IT-05 | 达到击杀上限 | 全员收到 RoundEnd + 排名，房间回 Waiting 可再来一局 |
| IT-06 | 对局中 B 断线 | 快照中 B 坦克继续行动（AI 托管），回合不中断 |
| IT-07 | B 60s 内携带 token 重连 | 恢复原身份与计分；超时后重连按新玩家/判离场 |
| IT-08 | 非法消息（未进房发 input、超频 input、坏 JSON） | 连接被限流/踢出，服务器不崩溃 |
| IT-09 | 8 坦克（真人 + AI 合计）满房跑完一局 | 无内存泄漏迹象（实体清理），无未捕获异常 |
| IT-10 | 双人同时申请最后一个房位（竞态） | 仅一人成功 |

## 4. L3 E2E 测试用例（Playwright，真实浏览器）

前置：测试钩子以测试模式启动真实服务器（随机端口、固定种子、加速倒计时）。

| 用例 | 步骤 | 断言 |
|---|---|---|
| E2E-01 冒烟 | 打开 3 个页面 → 加入同一房间 → 房主开始 | 3 页均渲染战场画面；HUD 显示 3 名玩家 |
| E2E-02 操作 | 页面 A 发送键盘事件（方向键+射击）移动并击毁 AI | 页面 A 击杀数 +1（积分 +100）；三页计分板一致 |
| E2E-03 结算 | 配置 200 分积分上限（= 2 杀），脚本完成 2 杀 | 三页均显示结算排名，"再来一局"可回房 |
| E2E-04 断线 | 对局中关闭页面 B 的 context | 页面 A/C 收到掉线播报；对局继续 |
| E2E-05 单机 | 离线进入单机模式 | 无网络请求，可移动/射击/被 AI 击毁重生 |

E2E 断言策略：优先断言 DOM/HUD 文本与 Canvas 像素采样（`ctx.getImageData` 抽样关键区域），不依赖像素级截图对比（抗素材迭代）。

## 5. L4 手动联机测试清单（里程碑验收）

- [ ] 主机启动，Windows 防火墙首次提示可放行；其他设备浏览器输入 IP 加入 ≤ 30 秒
- [ ] Chrome / Edge / Firefox 各 2 台真机混跑一局，无卡顿/花屏/音画不同步
- [ ] 操作手感主观评价：转向吸附、冰面滑行、爆炸时序与原版（模拟器对照）无明显偏差
- [ ] 局域网内操作→画面反馈感知延迟 < 50ms（录屏逐帧法测量）
- [ ] 全程 10 分钟对局无掉帧、内存稳定（DevTools Performance/Memory）
- [ ] 手机/平板浏览器打开页面给出明确"请使用桌面浏览器"提示（降级体验）

## 6. L5 性能验收指标

| 指标 | 目标 |
|---|---|
| 服务器单 tick 模拟耗时 | < 5ms（8 坦克真人 + AI 满负载） |
| 快照包大小 | < 5KB/tick（全量，8 实体） |
| 客户端渲染帧率 | 稳定 60fps（中端笔记本，1x~3x 缩放） |
| 加入房间 → 可操作 | < 1s（局域网） |

## 7. 验收标准（Definition of Done）

1. L1/L2 全部通过，`shared/sim` 行覆盖 ≥ 95%。
2. L3 冒烟（E2E-01/02）每次合并通过；全量 E2E 发布前通过。
3. L4 清单在 M2（2 人）、M4（6 人）里程碑各执行一轮并记录结果。
4. 需求文档 §3 非功能需求 NFR-1~5 逐条验证通过。

## 8. 缺陷管理约定

- 阻断联机/崩溃/计分错误 → P0，合并阻塞；手感/平衡类 → P1 记录到"参数对照表"迭代；视觉/音效瑕疵 → P2。
- 所有手感类缺陷必须附：操作步骤 + 录屏（或逐帧描述）+ 与原版模拟器对照说明。
